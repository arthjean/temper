# Temper v0.0.3

Temper v0.0.3 is an experimental Linux Cargo subcommand. Its CLI and schema-3
report may change incompatibly during `0.x`.

v0.0.3 changes one thing: Cargo, not Temper, now owns every compiler input of a
PGO build. The [v0.0.1 user contract](v0.0.1.md) still describes the CLI,
measurement, decision and durability behaviour, which are unchanged. This
document records only what v0.0.3 adds or narrows. The report contract is
[`schema-v3.md`](schema-v3.md), the executable boundary is
[`pgo-compatibility-matrix-v1.md`](pgo-compatibility-matrix-v1.md), and the
evidence discipline is [`verification-v0.0.1.md`](verification-v0.0.1.md).

## What changed

Up to v0.0.2, Temper reconstructed the project's rustflags and re-published them
through its own `CARGO_ENCODED_RUSTFLAGS` during PGO. That reconstruction read
only directly discovered Cargo configuration files, so any flag reaching rustc
through a Cargo `include` file was silently dropped from both PGO phases while
schema-2 parity still reported a match. The defect is reproduced, not inferred,
in [`evidence/interposition/2026-07-28`](evidence/interposition/2026-07-28).

v0.0.3 removes the reconstruction. Temper no longer synthesizes
`CARGO_ENCODED_RUSTFLAGS`. Cargo resolves the compiler inputs exactly as it
normally would, and a private compiler shim appends the PGO phase controls after
Cargo has resolved them.

## Compiler interposition

For the PGO subpipeline only, Temper sets a process-local `RUSTC` to its own
installed executable and passes a private, versioned protocol describing the
real rustc, the stage, the target triple, the stage target directory and the
stage capture directory. The executable dispatches that protocol before any
command-line parsing; it is internal, is never a public subcommand, and appears
in no help output.

The shim forwards raw Unix argument bytes with no shell evaluation and replaces
itself with the real rustc, so exit status, signals and the three standard
streams are preserved. It appends a phase control only to a real target
compilation, identified by the exact supported `--target` together with a
compilation `--emit` and no `--print`. Cargo probes, host build scripts and proc
macros are always passed through untouched.

Baseline and static-candidate builds are not interposed. Their Cargo behaviour,
including any wrapper the project configures, is unchanged.

## Four interposed stages

A PGO attempt now runs four interposed builds, each in a unique, initially
absent target directory and capture directory:

| Stage | Appended controls |
|---|---|
| `pgo_reference` | none, pass-through observation of the selected base strategy |
| `pgo_generate` | one absolute `-Cprofile-generate=...` |
| `pgo_use` | one absolute `-Cprofile-use=...` plus `-Cllvm-args=-pgo-warn-missing-function` |
| `pgo_confirmation` | the same controls as the accepted `pgo_use` build |

Shim-appended flags are invisible to Cargo unit fingerprints, so a reused,
pre-existing, symlinked or canonically aliased stage directory is rejected
before Cargo starts.

## Observed parity

Each shim invocation writes one bounded, create-new evidence record before
replacing itself with rustc. A record holds structural crate fields, the
invocation class and ordered length-framed digests of the raw argument bytes. It
never holds unrestricted argv, and no report publishes one.

Parity is computed only after the reference, generation and use builds have all
executed, keyed by logical crate identity. Normalization permits exactly one
class of difference: substrings equal to the stage target root. Everything else,
including `-Cmetadata` and `-Cextra-filename`, must compare equal. Any other
added, removed, reordered or changed compiler input rejects PGO with
`compiler_input_mismatch`, and confirmation revalidates the same contract before
promotion. No parity object can report a match without complete evidence.

## Cargo configuration provenance

Temper follows Cargo 1.94 `include` recursively for provenance and safety only.
It records canonical source paths, SHA-256 hashes and include edges in load
order, and it never merges configuration values or reconstructs effective
rustflags. A missing optional include is recorded; a missing required include, a
cycle, a malformed entry, an unreadable file or a source that changes while it
is hashed fails closed. A configuration that uses stable `include` on Cargo
below 1.94 is rejected with the version boundary and no nightly opt-in.

## Narrowed boundary

The v0.0.1 supported boundary still applies. v0.0.3 narrows it further for PGO
only:

- Any nonempty ambient `RUSTC_WRAPPER`, `RUSTC_WORKSPACE_WRAPPER`,
  `CARGO_BUILD_RUSTC`, `CARGO_BUILD_RUSTC_WRAPPER` or
  `CARGO_BUILD_RUSTC_WORKSPACE_WRAPPER` rejects only PGO before the reference
  build.
- Any `build.rustc`, `build.rustc-wrapper` or `build.rustc-workspace-wrapper`
  declared anywhere in the discovered configuration graph, including through
  nested `include`, rejects only PGO and names its declaring source.
- An existing `-Cprofile-generate`, `-Cprofile-use` or `-Cinstrument-coverage`
  in the resolved compiler arguments rejects only PGO before the conflicting
  command reaches rustc.

A compiler wrapper sits outside the shim, so it can compute a cache key before
the phase control exists and serve a PGO phase from a non-instrumented artifact.
That was demonstrated, not assumed, in the EP-001 evidence. No wrapper-specific
bypass, environment tweak or cache-disable flag exists; wrapper support requires
a separate proof that the wrapper key includes the effective phase controls.

Every rejection above is nonfatal: the bounded search continues, and a valid
static candidate can still be confirmed and promoted. An interposition or
evidence failure on a baseline or static build stays fatal, because that
artifact would be unproven.

## Run evidence

Run layout and durability ordering are unchanged. `run.json` is now schema 3 and
adds a compiler-interposition record per interposed build, a per-stage capture
aggregate, the Cargo configuration source graph, compiler-input environment
digests, the observed parity object and bounded compiler decisions. Historical
schema-1 and schema-2 records are never migrated, rewritten or reinterpreted.

## Explicit non-goals

Every v0.0.1 non-goal still applies. v0.0.3 additionally does not add an
optimization strategy, change measurement-v1, separate PGO training from
evaluation workloads, reimplement Cargo configuration merging, import Cargo or
rustc internals, expose a public compiler shim or wrapper protocol, support a
custom `build.rustc` or any compiler wrapper during PGO, or change the corpus-v1
contract.
